# Training Copilot v0.2 产品与开发需求说明

## 1. 项目背景

当前 Training Copilot v0.1 已完成最基础的线下培训项目管理能力，包括：

- 线下培训模板初始化；
- 创建项目；
- 根据培训日期及节点时间偏移自动生成任务；
- 节点、任务、项目基础关系；
- 项目总览、项目日历、节点任务查看。

现有 `Offline Training v1.0` 不废弃。

该模板来自真实线下培训运营经验，覆盖培训目标、预算、讲师、场地、物料、现场执行、宣传、报销、复盘等共性流程，后续应定位为：

> **底层“单次线下培训活动模板”**

而不是整个 Training Copilot 的唯一项目模板。

v0.2 的目标是在现有底层能力上增加：

> **培养项目层 + 项目运营协同层 + 进度风险判断层。**

---

## 2. v0.2 产品定位

Training Copilot v0.2 定位为：

> **面向培训项目经理、项目执行人员和管理者的培训项目运营工作台。**

核心价值：

### 对项目经理
快速掌握项目总体进度、近期重点、专项需求、风险与节奏，减少人工追问和信息汇总。

### 对项目执行人员
明确自己负责什么、什么时候完成、当前进度、完成标准及相关备注/SOP。

### 对管理者
能够快速看到项目阶段、完成进度、项目成果、风险、培训场次、覆盖人群等关键信息。

---

## 3. 产品设计原则

本版本优先解决：

> 看得清、找得到、知道谁负责、知道什么时候完成、能看项目节奏、能提前发现风险。

不要在 v0.2 中扩展成完整采购、财务、审批或企业协同系统。

本版本不接入企业微信，不读取企业微信消息，不自动向外部系统推送。

当前仅作为内部试用工具。

---

## 4. 核心项目架构升级

现有：

> 项目 → 节点 → 任务

升级为：

> **培养项目 → 届别/批次（可选） → 培养活动/培训场次 → 节点 → 任务 → 子任务**

其中“届别”不是强制字段。

### 管培生项目示例

管培生项目  
→ 2024届 / 2025届 / 2026届  
→ 线下培训 / 线上学习 / 行动学习 / 开营 / 结营  
→ 具体线下培训继续调用 `Offline Training v1.0`

### 人才400 / 恒业101示例

培养项目  
→ 本年度学员  
→ 线下培训1 / 线上学习 / 作业 / 线下培训2 / 结业

### 大学生训练营示例

培养项目  
→ 年度大型训练营  
→ 前期设计 / 资源准备 / 多日交付 / 现场执行 / 宣传 / 复盘

---

## 5. 三类培养项目模板

### 5.1 年度大型综合培训项目

适用：

> 大学生迎新训练营等。

特点：

- 一年一次；
- 项目准备周期长；
- 可提前至 T-120；
- 单次项目可能连续执行多日；
- 参与人数多；
- 多方协作复杂；
- 物料、预算、宣传、现场等专项工作量大。

主要阶段建议：

> 项目设计  
> 人员与嘉宾协调  
> 资源与物资准备  
> 课程与内容准备  
> 现场执行  
> 宣传产出  
> 项目复盘

第一版模板骨架可参考现有大学生项目运营表，但不要一次写死所有细节，应支持后续调整。

---

### 5.2 多届并行长期培养项目

适用：

> 管培生项目。

特点：

- 同时存在多个届别；
- 各届人数不同；
- 各届培养周期不同；
- 一年多次培训；
- 每年可能同时存在开营、正常培养和结营；
- 不同事业部可能同时安排培训。

必须支持：

#### 届别管理

每届记录：

- 学员人数；
- 培养周期；
- 当前状态；
- 整体进度；
- 已完成培训次数；
- 下一关键活动；
- 是否已结业。

#### 年度培训地图

横轴：

> 1月—12月

可按：

> 届别

或

> 事业部

显示计划培训时间。

v0.2 第一版优先实现可视化时间看板，自动冲突识别可作为后续增强项。

---

### 5.3 年度持续培养项目

适用：

> 人才400、恒业101、内训师等。

特点：

- 同一年度主要只有一届；
- 一年中发生多次线上和线下培养；
- 一般一年内结业或认证；
- 不需要复杂的多届并行。

支持活动类型：

> 线下培训 / 线上培训 / 作业 / 实践 / 调研 / 认证 / 结业

其中“认证”为可选能力，适用于内训师项目。

## 6. 功能一：任务与节点工作台升级

当前任务不再只是一个勾选框。

每个任务至少支持以下字段：

| 字段 | v0.2要求 |
|---|---|
| 任务名称 | 必须 |
| 所属节点 | 必须 |
| 开始时间 | 必须 |
| 截止时间 | 必须 |
| 负责人 | 必须 |
| 状态 | 必须 |
| 完成进度 | 必须 |
| 进度备注 | 必须 |
| 子任务 | 支持 |
| 完成标准 | 支持 |
| 普通备注 | 支持 |
| 关联SOP/文件 | 支持 |
| 完成质量评分 | 支持 |
| 复盘反馈 | 支持 |

统一状态：

> 未开始 / 进行中 / 阻塞 / 已完成 / 已取消

完成进度：

> 0–100%

如存在子任务，默认按子任务完成比例自动计算。例如4个子任务完成3个，自动进度为75%。

允许PM人工调整。

进度备注允许填写：

> 初稿已完成 / 还差3份 / 等待上级确认 / 等待供应商回复

## 9. 预算与采购 v0.2

该模块当前只解决：

> **预算前期估算 + 预算申请进度透明。**

不要开发完整采购或财务系统。

真实业务链路：

> PM与项目组确认需求  
> → PM需要了解各项预计金额  
> → 当前需要逐项询问供应商对接同事  
> → PM汇总金额  
> → PM交给预算负责人  
> → 预算负责人在公司系统申请

当前最大痛点：

> **PM负责汇总预算，但PM并不知道每一项大概多少钱，导致大量重复询问。**

### 预算需求表

至少包含：

| 字段 | 示例 |
|---|---|
| 费用项 | 茶歇 |
| 是否涉及 | 是 |
| 数量/人数 | 100 |
| 参考价格 | 30元/人 |
| 预估金额 | 3000 |
| 备注 | 两天 |
| 是否已确认 | 是 |

第一版预置常见费用项：

- 外请讲师；
- 茶歇；
- 外部摄影/视频拍摄；
- 学员手册；
- 常规物料制作；
- 奖品；
- 定制礼品；
- 其他。

允许手动新增。

---

## 10. 参考价格库

新增轻量级：

> **参考价格库**

目的不是正式报价，而是辅助PM做项目预算测算。

字段：

- 费用项；
- 参考单价或价格区间；
- 单位；
- 最近更新时间；
- 备注。

页面必须提示：

> **参考价格仅用于预算前期测算，实际价格以最终报价为准。**

PM勾选预算项后，可自动带出参考价格，并计算预计金额。

---

## 11. 预算申请进度

预算需求确认后自动形成：

> 项目预算汇总

至少显示：

- 各费用项；
- 预计金额；
- 预计总金额；
- 预算负责人；
- 计划申请时间；
- 实际申请时间；
- 当前状态；
- 备注。

状态：

> 待确认 / 待申请 / 已提交 / 审批中 / 已通过

v0.2 不做：

> 合同 / 发票 / 报销 / 付款 / 验收

## 12. 物料需求 v0.2

不要把现有复杂物料Excel全部复制进系统。

v0.2 只保留：

| 字段 | 要求 |
|---|---|
| 物料名称 | 必须 |
| 数量 | 支持 |
| 尺寸/规格 | 支持 |
| 负责人 | 必须 |
| 内容提供截止时间 | 支持 |
| 预计交付时间 | 支持 |
| 当前状态 | 必须 |
| 备注 | 支持 |
| 是否计入预算 | 支持 |

状态：

> 待确认 / 进行中 / 阻塞 / 已完成 / 已取消

第一版默认常见物料：

> 展架 / 横幅 / 学员手册 / 席卡 / 地贴 / 海报 / 指引牌 / 证书 / 奖品或礼品 / 其他

- 复杂设计状态；
- 制作状态拆分；
- 供应商详细数据库；

价格统一由预算模块管理。

## 13. 宣传需求 v0.2

真实业务：

> PM提出宣传需求  
> → 宣传小组确认  
> → 宣传小组负责制作

目前没有严格审批链路。

支持需求类型：

- 新闻稿/图文稿件；
- 海报/长图；
- 现场摄影；
- 培训回顾视频；
- 采访视频；
- 最佳实践；
- 学员故事；
- 其他。

默认一次线下培训可以建议：

> 图文/新闻稿 ×1  
> 回顾视频 ×1

但允许删除、修改或新增。

字段：

- 内容类型；
- 形式；
- 数量；
- 负责人；
- 开始时间；
- 预计完成时间；
- 状态；
- 备注。

状态：

> 需求确认 / 素材准备 / 制作中 / 待确认 / 已完成 / 已发布

不做正式审批流。

## 14. 预算、物料、宣传之间的轻关联

避免三个模块完全割裂。

例如：

- 物料“学员手册”勾选“是否计入预算=是”，预算模块可建立对应费用项；
- 宣传“外部摄影=是”，可关联外部摄影预算；
- 定制礼品可关联定制礼品预算。

v0.2 只做简单引用关系，不做复杂双向流程自动化。

## 17. 项目进度预警

v0.2 新增核心能力：

> **项目健康度与进度预警**

至少判断以下情况：

### 17.1 任务逾期
截止时间已过但未完成。

### 17.2 任务临近截止
进入预警窗口仍未完成。

### 17.3 关键节点风险
关键节点临近，但相关关键任务未完成。

### 17.4 项目节奏偏慢
例如：

> 时间进度 = 70%  
> 任务完成进度 = 45%

则提示：

> 项目进度低于时间进度。

### 17.5 长期未更新
关键任务超过一定时间没有任何更新。

### 17.6 专项进度异常
例如项目总体进度70%，宣传进度仅20%，则提示专项工作可能滞后。

## 18. 健康度

统一三种状态：

> 正常 / 需要关注 / 风险

第一版规则不用追求复杂AI模型，优先使用确定性规则。

预警必须尽可能显示：

- 风险名称；
- 风险原因；
- 当前数据；
- 建议动作。

## 25. 界面重构

> **具体培训活动 / 培训场次详情页**

- 项目总览；
- 我的项目；
- 日历与待办；
- 需求协同；
- 风险预警；
- SOP与资料；

- 商务；

## 27. Daily Sync 后续方向

当前保留现有设计方向：

> Daily Sync  
> → 信息识别  
> → 建议变更  
> → 用户确认  
> → 更新项目  
> → 风险判断  
> → 项目简报

但 v0.2 本轮不要优先投入复杂AI。

后续可扩展：

> 多模块负责人语音输入  
> → 语音转文字  
> → 自动识别所属项目/模块/任务  
> → 提取进度关键词  
> → 生成建议变更  
> → 用户确认后更新

系统数据库设计时需要避免把“项目动态来源”写死。

## 30. 本版本的范围控制原则

v0.2 的重点不是做完整企业级项目管理系统，而是先把以下能力跑通：

- PM推进方便；
- 执行人员节点明确；
- 负责人清楚；
- 需求透明；
- 项目节奏清晰；
- 风险提前可见；
- 管理者能够快速看数据；
- 复盘时能够直接获得过程数据。

第二版优先解决信息协同和项目判断，不追求一次性覆盖完整业务流程。
